# 2. 為什麼 LLM 容易受到 Prompt Injection？

## 初學者版說明

LLM 會讀取文字並依照指令產生回應，但它處理的內容可能同時包含「要遵循的指令」和「只需要閱讀、摘要或轉換的資料」。多份來源指出，現有常見輸入形式沒有可靠的邊界，能讓模型永遠正確辨別每段文字的來源與角色。因此，資料裡看起來像命令的文字也可能被模型當成指令。（S2，PDF p. 1；S5，PDF p. 1；S6，PDF p. 1）

用郵件助理來想像：任務指令是「摘要郵件」；郵件正文則是待處理資料。如果正文內含另一段命令，模型可能難以只靠文字本身判斷它是「郵件內容」還是「新指令」。這個例子是依照來源對指令／資料混在同一輸入的描述所作的教學化轉述，不是額外的實驗結論。（S2，PDF p. 1；S6，PDF pp. 1–2）

## 各來源的說法

- **AgentDojo** 說 LLM 直接處理文字，缺少正式機制區分指令與資料；攻擊者可把惡意指令放進代理人透過工具讀取的第三方資料。（S2，PDF p. 1）
- **StruQ** 指出 Prompt Injection 利用了模型遵循指令的能力，以及無法分開辨認 prompt 和 user data 的弱點；因此提出以 Structured Queries 分開兩種輸入。（S6，PDF p. 1）
- **Spotlighting** 說常見應用會把多種輸入串接成單一文字流，模型難以分辨不同輸入來源；其方法用轉換方式提供來源訊號。（S5，PDF p. 1）

## 初學者要記住

問題不只是「有人寫了奇怪文字」，而是應用程式把模型要遵守的指令和模型要處理的內容交給同一個模型後，模型可能混淆兩者。以上是各來源支持的共同問題描述；來源對模型內部如何處理此問題沒有在本批材料中提供統一的單一解釋，因此不再延伸推論。
