防禦方向一：分清指令與資料

STRUCTURED QUERIES · StruQ

把 prompt 與 data 分開

07 · 方法本身的限制

防禦方法各有適用範圍

方法已知限制
Delimiting攻擊者仿造界定符可能造成混淆。
Datamarking靜態標記若只處理空格，可能漏掉無空格文字。
Encoding較弱模型可能解碼或完成下游任務時出錯。
Tool filtering受工具需求能否事先規劃，以及正常任務與攻擊是否共用工具所限。
Detector／StruQDetector 可能誤判正常內容；StruQ 有其適用範圍。
本頁聚焦各方法的質性限制；實驗數字與設定見下一頁。
來源：S5，PDF pp. 4–6；S2，PDF p. 9；S6，PDF pp. 10、14。

09 · 結論與證據邊界

目前能否說「已經完全防禦」？

目前知道

多種防禦方法有具體限制與部分未解問題。

資料不足
／尚無定論
仍未確定

是否能防禦所有 Prompt Injection，或有適用所有系統的完整解法。

不能據此說「已證明完全防禦不可能」，也不能宣稱已有完整防禦。
